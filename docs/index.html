Overview

This project implements an ETL (Extract, Transform, Load) pipeline using Apache Airflow to build a data foundation for a RAG (Retrieval-Augmented Generation) research assistant. The pipeline fetches research papers from arXiv, processes them, and stores structured data in PostgreSQL for downstream AI applications.

Asset-Driven Workflow Benefits

Decoupled DAGs

Each stage is independent and reusable

Event-Driven

Downstream tasks only run when data is ready

Fault Tolerance

Failed stages don't block unrelated workflows

Scalability

Easy to add new consumers of the same assets

Key Components

1. Extract DAG

Schedule: Daily (@daily)

Purpose: Fetches research papers from arXiv API

  • Incremental extraction using counter file
  • Fetches 50 papers per run (configurable)
  • Rate limiting (3-second delay between requests)
  • Stores raw XML responses

2. Transform DAG

Schedule: Daily (@daily)

Purpose: Parses XML and extracts PDF content

  • XML parsing with namespace handling
  • PDF download and text extraction (first 3 pages)
  • Content cleaning and paragraph extraction
  • Structured JSON output with metadata

3. Load DAG

Schedule: Asset-triggered by transformed_asset

Purpose: Loads processed data into PostgreSQL

  • Automatic table creation
  • JSONB storage for arrays and nested data
  • Stores paper metadata, summaries, and PDF content

4. Orchestrator DAG

Schedule: Daily (@daily)

Purpose: Coordinates the entire ETL pipeline

  • Sequential execution: Extract → Transform → Load
  • Waits for each stage to complete before proceeding
  • Centralized pipeline management

Data Flow

Extraction Phase

arXiv API → Raw XML → data_extract.xml

Transformation Phase

XML → Parsed Metadata + PDF Content → data_transform.json

Loading Phase

JSON → PostgreSQL (research_papers table)

Setup & Deployment

Prerequisites

  • Docker & Docker Compose
  • 4GB+ RAM
  • 10GB+ disk space

Quick Start

  1. Navigate to project: 
    cd Research_Paper_Airflow_ETL
  2. Start services: 
    docker-compose up -d
  3. Access Airflow UI:

    URL: http://localhost:8080

    Username: airflow | Password: airflow

  4. Trigger Pipeline:

    Enable arxiv_etl_orchestrator DAG and click "Trigger DAG"

Key Features

Incremental Processing

Counter file tracks last processed position, prevents duplicate downloads, and resumes from last checkpoint.

Error Handling

PDF extraction failures logged but don't block pipeline. Database transactions ensure data consistency.

Scalability

Celery workers enable parallel task execution. Asset-based triggering prevents unnecessary runs.

Data Quality

XML namespace handling for robust parsing. PDF content cleaning and JSONB storage preserves complex structures.

RAG Integration

This pipeline prepares data for RAG applications by:

  • Structured Storage: PostgreSQL enables efficient querying
  • Text Extraction: PDF content ready for embedding generation
  • Metadata Preservation: Authors, categories, dates for filtering
  • Incremental Updates: Daily additions without reprocessing

Typical RAG Workflow:

User Query → Vector Search → Retrieve Papers → LLM Context → Response
